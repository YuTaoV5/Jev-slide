# 三段中文训练动画：讲稿补充源

本文件由 build_slides_v4.py 按 RLHF / RLVR / RLCD 小节插入逐页讲稿。时间表示视频时间，不是整页演讲时长；每段视频32秒，建议整页讲解约90秒。第一次可连续播放并使用表中的短句，第二次暂停解释关键画面。动画静音，口播由演讲者完成。

## RLHF

**开场口播**：我们先看人类偏好是怎样变成训练信号的。沿着图的上排从左向右，再从下排回到策略模型。这里有两种模型：一个负责回答，一个负责给回答打分。

| 视频时间 | 指向中文画面 | 可直接讲的短句 |
| --- | --- | --- |
| 00–04秒 | 人工示范 → 监督微调 | 先用人工示范，让模型学会怎么回答。 |
| 04–08秒 | 策略模型 → 采样回答 | 再让它对同一个问题生成候选回答。 |
| 08–12秒 | 候选回答 A / B | 这里有两个回答，交给人来比较。 |
| 12–16秒 | 人工排序：A 优于 B | 人更喜欢 A，这就是一条偏好标签。 |
| 16–20秒 | 拟合奖励模型 | 奖励模型学习预测这样的偏好。 |
| 20–24秒 | 奖励分数 → 参数更新 | 再用奖励模型给新回答评分。 |
| 24–28秒 | PPO + KL → 策略模型 | 用奖励更新策略，同时限制变化过大。 |
| 28–32秒 | 全部模块亮起 | 重复这个过程，让回答更符合人类偏好。 |

**暂停深讲（建议17秒、25秒）**：

- 17秒：指向“奖励”。`P(A > B)`表示这个偏好算例中“A胜过B”的预测概率，不是A的事实正确率。奖励模型拟合偏好排序之后，可以为新的回答提供训练分数。
- 25秒：指向“PPO + KL”。PPO是这里采用的经典策略更新方法；KL约束让模型不要为了拿高分而过度偏离参考策略。先解释用途即可，不必在这里推导公式。
- 此动画讲的是经典RLHF训练流程。线上生成一个回答时，不需要再等人现场排序，也不会重新训练奖励模型。

**术语口语解释**：SFT＝跟着示范学习；策略模型＝产生回答的模型；奖励模型＝学习人类偏好的评分模型；PPO＝用奖励调整回答策略的方法；KL＝约束策略改变幅度的量。

**领导可能追问**：

- **有人偏好一个回答，就说明它正确吗？** 不一定。偏好可能受到表达方式、完整性等影响，事实正确性要有相应的评估或验证。
- **图上的分数是实际大模型训练结果吗？** 不是。A/B回答是教学示意，数值是本地小规模偏好拟合计算；本轮没有训练或调用真实模型。
- **现在所有偏好训练都必须用PPO吗？** 不需要。这页只解释经典流程，不把它当作所有偏好训练方法的统一实现。

**转场**：如果任务有明确标准答案或测试程序，我们能不能直接用验证结果作为奖励？下一页看RLVR。

## RLVR

**开场口播**：这次，反馈来自能执行的规则或测试。请注意左上角只给模型问题，参考答案放在右下角验证器里，不能先泄漏给模型。

| 视频时间 | 指向中文画面 | 可直接讲的短句 |
| --- | --- | --- |
| 00–04秒 | 问题：2 + 3 = ? | 先给一个可以验证答案的问题。 |
| 04–08秒 | 策略模型 → 生成文本答案 | 模型先生成答案，之后才验证。 |
| 08–12秒 | 答案 A：5；答案 B：6 | 本例得到5和6两个候选答案。 |
| 12–16秒 | 验证器：参考答案5 | 验证器拿参考答案逐一比较。 |
| 16–20秒 | 奖励：A → 1；B → 0 | 答对得1分，答错得0分。 |
| 20–24秒 | 参数更新 | 根据这些奖励，调整模型策略。 |
| 24–28秒 | 返回策略模型 | 再换任务，继续采样和更新。 |
| 28–32秒 | 目标：答案正确 | 目标是提高生成答案的正确率。 |

**暂停深讲（建议13秒、29秒）**：

- 13秒：指出“只给问题”和“参考答案：5”位于不同模块。算术可以比答案，代码任务可以运行测试；实际奖励设计可能还要考虑格式等要求。本动画只画最简单的正确性反馈。
- 29秒：答得更对，与报出的概率是否可信，是两个评价问题。例如自称90%有把握的一组判断，需要检查这一组是否确实约90%正确；单纯对正确答案给1分，并没有自动解决这个问题。
- 这是训练时的验证回路。部署后是否每次都调用验证器，是应用系统另外的设计选择。

**术语口语解释**：RLVR＝用可验证奖励做强化学习；验证器＝执行规则、标准答案比较或测试的程序；策略更新＝让模型之后更倾向产生获得高奖励的答案。

**领导可能追问**：

- **奖励为1，是否就代表100%可靠？** 不代表。它表示这个样本通过了当前验证规则；验证器覆盖不完整时，真实任务仍可能出错。
- **kernel问题定位也可以直接判对错吗？** 部分环节可以，例如复现、定向测试和补丁前后对照。但真实故障的根因往往没有即时标准答案，要设计可复核证据，不能用“日志看起来相关”充当确定标签。
- **Jev的训练是不是就叫RLVR？** 官方介绍使用RLCD这个名称。本页是对照路线，下一页讨论Jev强调的校准决策目标。

**转场**：我们不仅希望选对，还希望程序知道什么时候该继续查、什么时候需要人工介入。因此还要看概率能不能经得起实际结果检验。

## RLCD

**开场口播**：Jev强调的是可供程序使用的决策概率。下面用一个可以复算的小例子，说明“概率诚实”是什么意思。它帮助理解训练目标，不是公开的Jev训练配方。

| 视频时间 | 指向中文画面 | 可直接讲的短句 |
| --- | --- | --- |
| 00–04秒 | 状态与问题 | 给定上下文，提出一个有限选项问题。 |
| 04–08秒 | 预测分布：是0.90，否0.10 | 模型直接给出“是”和“否”的概率。 |
| 08–12秒 | 同类样本：6是 / 4否 | 这组教学样本，十次里有六次为是。 |
| 12–16秒 | 真实结果 → 示例评分 | 把整个概率预测与真实结果比较。 |
| 16–20秒 | 对数损失0.984 | 过度自信地预测错误，会受到惩罚。 |
| 20–24秒 | 示例参数更新；概率条变化 | 调整示例参数，让概率接近实际频率。 |
| 24–28秒 | 是0.60；损失约0.673 | 在这一组里，六成比九成更合适。 |
| 28–32秒 | 小结：Jev路线RLCD | 这是群体校准，不是单次正确保证。 |

**暂停深讲（建议17秒、25秒）**：

- 17秒：这里固定了一组信息条件可比较的教学样本，其中6个“是”、4个“否”。如果一直报“是的概率90%”，遇到那4个“否”时就会产生较大损失。预测并没有创造真实结果，两者分别送入评分环节。
- 25秒：平均对数损失从约0.984降到0.673。它不是正确率，也不是耗时，而是这个教学例子的评分，越低越好。同一组的最合适概率是0.60，不意味着所有问题都应该输出0.60。
- 动画用单参数梯度下降展示变化。Jev的精确损失和优化器未由当前所读官方资料公开，所以不要把画面中的log loss称为Jev已证实采用的实现。
- 真正评估校准需要足够多、与目标任务相符的独立样本。这里10个固定样本只是解释机制，不能据此宣称真实系统已经校准。

**术语口语解释**：RLCD＝官方命名的校准决策训练路线；概率分布＝各选项分别有多大可能；校准＝在可比较的一组判断里，预测概率与实际发生频率相符；对数损失＝衡量概率预测质量的一种评分方法。

**领导可能追问**：

- **是不是调低置信度就能变得更可靠？** 不是。概率需要与信息条件下的真实发生频率匹配；没有验证地统一调低或调高，都不能保证改善。
- **同样选“是”，0.60和0.90有什么业务区别？** 排名可能不变，动作可以不同。例如证据不足时补查、转人工，风险较低且达到经验证阈值时才自动推进；阈值由错误成本和验证结果决定。
- **换到我们的kernel场景还会校准吗？** 不能直接保证。需要按故障类别、证据缺失程度和内核版本等检查分布变化，用本地数据验证概率及动作效果。
- **我们这次实现了Jev训练吗？** 没有。本次完成的是机制演示和离线分析；没有模型API调用，也没有真实模型权重训练。
